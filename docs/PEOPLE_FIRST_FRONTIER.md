# People-First Frontier

A practical interaction contract for interfaces that feel authored for people, not assembled from generic software patterns.

## Core loop

`notice → understand → choose → act → verify → recover`

Every important task should make the next step obvious and make consequential outcomes legible.

## Phone-first rules

- Design from 390px first; desktop expands the phone composition.
- Keep the primary action reachable by one thumb.
- Use 44px minimum touch targets where practical.
- Never hide critical status behind hover.
- Convert tables into summaries, cards, or drill-downs on narrow screens.
- Treat empty, loading, error, success, and offline-ish states as designed product states.

## Distinctive without confusion

Use controlled surprise:

- one memorable visual motif per surface;
- contextual reveals instead of permanent control walls;
- consequence previews before important actions;
- reversible optimistic interactions;
- motion that explains state, with reduced-motion support.

## Human language

Prefer concrete verbs: `send`, `review`, `fix`, `keep`, `share`, `pause`, `try`.

Avoid generic filler such as `seamless`, `revolutionary`, `unlock`, `supercharge`, `next-generation`, and `AI-powered` unless the wording is genuinely necessary.

## Trust pattern

For consequential actions expose:

`intent → scope → expected result → evidence → undo/rollback`

The product should feel capable because it is legible.

## Interaction vocabulary

- **Pulse** — compact confirmation of a state change.
- **Reveal** — secondary context shown when it becomes relevant.
- **Commit Preview** — preview of the consequence before committing.
- **Quiet Undo** — unobtrusive short reversal window.
- **Trail** — recent task path preserved for recovery.
- **Checkpoint** — explicit pause before an irreversible or externally visible action.
- **Proof Peek** — small evidence view supporting an important claim.

## Definition of done

A surface is ready when a first-time user can identify the primary action, understand its consequence, recover from mistakes, and use the experience comfortably on a phone without learning internal product terminology.
