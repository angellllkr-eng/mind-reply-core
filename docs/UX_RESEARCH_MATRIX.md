# NOVA UX Research Matrix

## Benchmark dimensions

| Dimension | Observed mature pattern | NOVA current state | Completion target |
|---|---|---|---|
| Discovery | Featured content + rails | Implemented | Verify on mobile |
| Navigation | Persistent categories | Implemented | Keyboard + screen-reader verification |
| Search/filter | Fast narrowing | Implemented | Add empty/error states |
| Live floor | Dedicated live surface | UI only | Keep demo until provider is contracted |
| Promotions | Eligibility + timing + T&Cs | UI/mock | Model rules separately from display |
| Rewards | Tier progression | UI/demo | Keep points synthetic until ledger exists |
| Account | Player/account surface | Template | Add real auth only in regulated track |
| Player protection | Safer-gambling access | Route exists | Implement market-specific controls only after counsel confirmation |
| Localization | Market language/currency | English foundation | Add verified Bulgarian translation set |
| Accessibility | Keyboard/ARIA/focus | Partial | Run repeatable AA audit |
| Performance | Mobile-first | CSS foundation | Record actual Web Vitals |
| Trust | Clear boundary/status | Demo boundary | Never imply licence without evidence |

## Research principle

Competitor products are used only to identify common information-architecture and interaction patterns. NOVA must use original branding, assets, copy and implementation.

Current public benchmark research also shows that mature operators make promotion rules, eligibility and expiry visible to users. NOVA should model those mechanics as data and policy, not hard-coded marketing text.
